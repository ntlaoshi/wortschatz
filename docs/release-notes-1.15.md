## Wortschatz 1.15

### 根因：拼写队列不是可观察状态

上一版把拼写改成「队列驱动」，队列用的是普通 `MutableList`。改队列不会触发界面重组，
于是出现两个看起来很怪的 bug：

- 答错后点「继续测试」，界面**还是原来那个词**（其实队列已经换了）
- 用户照着屏幕上的词拼写，判定却拿队列里的**新词**比对 → 怎么拼都判错，
  尤其是含 ß / 变音字母的词，会被误认为「ss 打不出来」

改用 `SnapshotStateList` 后，队列一变界面立即刷新，两个问题一起消失。

### 验证记录

| 步骤 | 结果 |
|---|---|
| 队列 `[Kissen, Brücke, Löffel]`，Kissen 故意答错 | 日志 `queue=[Brücke, Löffel, Kissen]`，界面立即切到 `首字母 B·····` |
| 输入 `bruecke`（ue 代替 ü） | `ok=true`，进度 1/3 |
| 点「跳过这个词」 | 队列变 `[Kissen]`，界面切到 `首字母 K·····` |
| 输入 `kissen` | `ok=true`，点「查看结果」进入结果页 |

### 加入跳过按钮

拼写题右下角新增「跳过这个词」：不计入通过，直接出队，避免某些词卡死整轮。
进度条与计数仍按「已通过数」显示，结果页会单列「跳过 N 个，未计入通过」；
全部拼对时标题仍是「全部拼对」，有跳过则显示「本轮完成」。

顺带把最后一题拼对后的按钮文案改成「查看结果」，不再是「下一题」。

### 复查：ß 与变音字母的判定本身没问题

`SpellTest.normalize` 一直把 `ä→ae、ö→oe、ü→ue、ß→ss` 双向归一，
`ok` 判定日志里 `bruecke` ↔ `die Brücke`、`heissen` ↔ `heißen` 都判对。
之前的「打 ss 不行」是上面的队列不同步造成的假象，不是比对逻辑的错。
